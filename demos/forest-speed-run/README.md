## 接入原仓库

本包包含独立游戏与可选接入补丁。上传内容仅包含新增的 `demos/forest-speed-run/`，不会自动应用补丁或修改原游戏入口。以下接入操作针对仓库本地副本；先保存已有改动。

1. 将本游戏目录放到 `xgnb/demos/forest-speed-run/`。
2. 将 `integration/museum-runner.js` 和 `integration/museum-runner-entry.js` 复制到 `xgnb/js/`。
3. 在 xgnb 仓库根目录检查补丁，再应用：

```sh
git apply --check demos/forest-speed-run/integration/xgnb-runner.patch
git apply demos/forest-speed-run/integration/xgnb-runner.patch
```

补丁针对上面的提交，修改三处：主入口加载接入脚本；剧情页加载接入脚本与场次入口；`novel.js` 为 `action: "runner"` 增加独立分支。不改原对白，不影响保安交涉或像素地牢战斗。若新版本或本地改动导致补丁检查失败，不要强行覆盖，按补丁内容人工合并这三处即可。

应用后，在第二十八场原对白结束时显示“跟随 MOSS 路线，进入追逐”。开局不授予通关标记，胜利结算才写入 `scene28Seen` 与场次完成记录。

需要从其他自定义入口启动时：

```js
MuseumRunner.launch({
  state: state,              // 当前剧情存档（可省略，默认读取当前账号）
  sourceScene: "scene-28",  // 中途退出返回该场次原位置
  returnScene: "scene-29",  // 成功后继续的场次
  completionFlag: "scene28Seen"
});
```

## 返回与存档约定

只有经 `MuseumRunner.launch()` 启动才显示“返回剧情”；独立游玩不读写主线结果。

- 游戏胜负留在本页，允许重试；点击“返回剧情”时才提交记录。
- 成功：进入 `returnScene`，保留主线生存点和地图坐标，写入跑酷完成记录。
- 失败后选择返回：生存点归零，进入仓库现有 `ending-d`；可在返回前重试。
- 中途退出：回到来源场次的阅读位置，不授予成功标记，不扣主线生存点。
- 正式账号使用 localStorage，课堂预览使用 sessionStorage，沿用仓库的 `museum_class_preview`。账号 ID 与每局 ID 必须同时匹配；保存成功后才消费结果；失败时保留记录供重试。

结果键是 `museum_pending_runner_v1`，字段为 `{version, kind, userId, runId, status, elapsed, score, distance, coins, wallHits}`。刻意不复用 `museum_pending_battle_v1`：原 `js/game.js` 的普通战斗胜利分支会发无脸面具并解锁蜡像馆，跑酷不应触发这些副作用。

接入应沿用原仓库的页面跳转方式，不建议未经适配直接塞进跨域 iframe。游戏与主页面必须同源，正式账号应使用仓库当前支持的本地静态服务或部署环境。
