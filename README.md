# 怪谈博物馆 · 交互故事

这是 Plan B 的浏览器小游戏原型（真的完全只是个最基本的原型，美术剧情剧情啥的还有大空缺）：玩家在二维房间里移动和调查，重要事件切入视觉小说对话；对话、战斗或小游戏结束后回到原来的地图位置。项目只使用 HTML、CSS 和原生 JavaScript。

```text
│  ├─ game.html           游戏流程说明与试玩入口

│  ├─ help.html           操作与玩法说明页面

```

## 运行和操作

直接在资源管理器中双击项目根目录的 `index.html`。浏览器会打开游戏主页，可以查看页面、进入地图并试玩当前 Demo。第一次进入先新建档案；档案和进度只保存在当前浏览器。独立注册页是 `pages/register.html`，其它公共页面从首页底部导航进入。进入地图后：

- 使用 WASD 或方向键移动。
- 靠近房间物品时按 `E` 调查；点击物品只作为辅助入口，仍需先走到交互范围内。
- 纸条、保安、规则告示、展台等调查点会打开视觉小说式剧情层。
- 宿舍钥匙打开大厅；完成保安交涉后解锁蜡像馆；出口选择构成当前原型结局。
- “保存”打开 20 个手动存档位；自动存档会持续更新，“读档”可以随时读取任意手动档。

当前地图由 Canvas 绘制，目的是先稳定验证玩法和坐标。美术组交付真正的二维房间素材后，可在 `js/game.js` 的 `drawRoom()` 中替换背景绘制，保留碰撞矩形和交互点数据即可。宿舍衣柜已接入两张同尺寸透明差分图：`assets/images/wardrobe-closed.png` 与 `assets/images/wardrobe-open.png`；它演示了“靠近高亮 → 按 E 改变物体状态 → 再次调查触发剧情”的完整流程。

标题页当前使用 `assets/images/title-dorm-bg.png` 作为低饱和旧宿舍背景；CSS 叠加了深色渐变，保证标题和按钮在不同屏幕尺寸下仍然清晰。后续美术组提供正式背景时，只需替换这张同名图片即可。

## 和剧情、美术、小游戏同学的协作方式

剧情同学只需要维护 `js/game.js` 中各调查函数里的对白、选项和状态变化；不要直接修改移动和存档逻辑。美术同学以房间设计稿提供物品的大致坐标、碰撞区域和交互名称，技术组再录入 `rooms` 配置。小游戏同学可以沿用战斗 Demo 的结果格式，结束时写入 `museum_pending_battle_v1`，主页面会在返回时自动接收结果。

## 课堂原型边界

`localStorage` 只适合课堂演示，不是真正的服务器账号系统；清理浏览器站点数据会同时删除账号和存档。所有核心流程不依赖网络，资源缺失时仍可运行 Canvas 版本。
